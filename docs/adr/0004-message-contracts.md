# 0004. Контракты: отдельный проект, тонкие команды, толстое событие

## Контекст

Сообщения ходят между тремя процессами. У двух из них есть база, у уведомлятора её нет и быть
не должно, а объявления типов ему нужны.

## Варианты

1. **Отдельный проект `Contracts` без единого пакета** — выбрано.
2. **Контракты в `Core`.** Тогда уведомлятор тащит за собой EF Core и Npgsql ради трёх классов.
3. **Дублировать объявления в каждом сервисе.** Так сделано с `RabbitSettings` — но настройки
   у каждого свои, а контракт обязан совпадать.

## Решение

`Corvette.MeteoExport.Contracts`: сообщения, `EndpointNames`, `ExportStatus`. Ссылки после
разделения: `Notifier` — только на контракты, `Api` и `Worker` — на контракты и `Core`, `Core` —
на контракты, из-за `ExportStatus` у сущности.

**Внутри контура сообщения тонкие** — только идентификатор задания:

```csharp
RunExportMessage    { Guid JobId }
FinishExportMessage { Guid JobId, string? ResultFilePath, string? Error }
```

Сообщение может пролежать в очереди минуты, а за это время задание уходит вперёд. Толстое сообщение
донесло бы устаревшую копию: база — источник правды, очередь переносит только повод что-то сделать.
Ключ файла и текст ошибки — не данные задания, а **исход попытки**: он рождается в ней самой, взять
его из базы неоткуда.

**Наружу уходит толстое событие**, и правило меняется на противоположное осознанно:

```csharp
ExportFinishedMessage { Guid JobId, ExportStatus Status, DateTime FinishedAt,
                        string? Email, string? WebhookUrl, string? Error }
```

У уведомлятора нет базы, читать исход ему неоткуда. Либо толстое событие, либо он ходит за исходом
в API по HTTP — вторая зависимость ради чистоты контракта не окупается.

Ключа файла в событии нет намеренно: ссылку уведомлятор собирает из своего адреса API и `JobId`,
а внутренний ключ корзины клиенту показывать нельзя.

## Последствия

- **Каждое поле толстого события — обещание, которое не забрать назад.** Добавить поле можно тихо,
  убрать — только с оговоркой всех подписчиков, поэтому «на будущее» в контракт ничего не кладём.
- Событие — снимок на момент публикации. Если задание когда-нибудь перезапустят, письмо уйдёт
  по данным того прогона, в котором родилось. Для уведомления допустимо, источник правды —
  `GET /exports/{id}`.
- Выделение проекта переименовало обменники: имя типа участвует в топологии
  ([ADR-0003](0003-masstransit-over-raw-client.md)), и они переехали с
  `Corvette.MeteoExport.Core.Messages:…` на `Corvette.MeteoExport.Contracts:…`. Старые остались
  в брокере пустыми, пока их не снесли руками; на стенде к тому моменту накопилось три поколения.
